OntoRAG

Ontology-grounded RAG over GitHub-as-storage datasets.

A reusable repository layout — an ontology (knowledge graph), content (chunked text), and embeddings — that a service reads to answer questions, plus a generic MCP server that serves graph-aware retrieval over any such dataset addressed by <org>/<repo>. The git repository is the database.

The dataset contract

A consumer reads manifest.json and follows the paths it declares. Everything is plain text / NDJSON / Turtle — diffable, versionable, host-agnostic.

ontology/world.ttl — RDF knowledge graph
ontology/entities.jsonl — flat entity index
content/chunks/*.jsonl — retrievable text, entity-linked
embeddings/vectors/*.jsonl — vectors, joined by id
schema/*.schema.json — the record contracts
manifest.json — the entry point

Three retrieval modes

modehowneeds an embedder?
vectordense cosine over the embeddingsyes
ontologyentity-graph (idf) + BM25 fallback — embedding-freeno
hybridsparse candidates → fetch their vectors → cosine re-rankyes

Retrieval eval on the Ars Magica reference dataset (recall@1) — for entity- and book-anchored queries, the graph modes far outrun plain vector:

Composition — packs you can add or remove

A dataset decomposes into a core plus modular packs (one per source document group), linked by a dc:requires dependency graph. Selecting packs and closing over their dependencies reconstructs a scoped world — the basis for access-scoping and per-source evaluation.

compose.py --packs covenants     # dc:requires pulls in the core
compose.py --validate            # integrity + soundness of the whole dataset

Run it

# HTTP MCP server (Docker), reading a dataset via Mirage's GitHub resource
docker compose up server                       # http://localhost:8765/mcp
claude mcp add --transport http ontorag http://localhost:8765/mcp

Serverless: with REDIS_URL + ONTORAG_RETRIEVAL=ontology, the index is materialized into Redis on a cache miss with a 24 h TTL and each request probes only the keys it needs — deployable on Vercel and friends.
